# Планер

Полноэкранный планировщик на русском языке: задачи и недельные цели, календарь, напоминания, расписание, привычки, планы и заметки. Интерфейс выполнен в небесно-голубой аниме-стилистике и адаптирован для desktop, планшетов и телефонов.

## Стек

- Backend: FastAPI, Pydantic 2, SQLAlchemy 2 (async), asyncpg, Alembic, PostgreSQL.
- Frontend: React, TypeScript, Vite, React Router, date-fns, Lucide React, CSS.
- Production: Docker Compose, Nginx, PostgreSQL.

## Структура

Backend расположен в `backend/app`: `auth` содержит регистрацию, вход, Argon2-хеширование паролей и JWT access token, `planner` — модели, схемы, репозитории, сервисы и роутер, `db` — async-сессию, `core` — настройки. Миграции находятся в `backend/migrations`.

Frontend расположен в `frontend/src`: `lib` содержит API-клиент, состояние и даты, `components` — общие элементы, `layout` — оболочку и меню, `pages` — страницы приложения, `assets` — графику.

Регистрация и вход доступны на странице frontend. Planner-данные изолированы по пользователю, а защищённые endpoint требуют заголовок `Authorization: Bearer <token>`. Refresh token, Redis-сессии и rate limiting пока не добавлены.

## Запуск через Docker Compose

Требуются Docker Desktop и Compose v2. В PowerShell из корня проекта:

```powershell
Copy-Item .env.example .env
```

Откройте `.env`, замените `change-me` на один и тот же надёжный пароль в `POSTGRES_PASSWORD` и `DATABASE_URL`, а `JWT_SECRET` — на длинную случайную строку. Затем:

```powershell
docker compose up --build -d
```

Миграции применяются отдельным одноразовым сервисом до запуска backend.

- Frontend: http://localhost:3000
- Backend health: http://localhost:8000/api/health
- Swagger: http://localhost:8000/docs
- ReDoc: http://localhost:8000/redoc

Остановить сервисы:

```powershell
docker compose down
```

Полностью удалить контейнеры и volume PostgreSQL:

```powershell
docker compose down -v
```

**Внимание:** ключ `-v` безвозвратно удаляет все данные PostgreSQL этого Compose-проекта.

## Локальный запуск backend

Требуются Python 3.11+ и доступный PostgreSQL. В PowerShell:

```powershell
Set-Location backend
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
alembic upgrade head
uvicorn app.main:app --reload --port 8000
```

В локальном `backend/.env` задайте `DATABASE_URL` в формате `postgresql+asyncpg://USER:PASSWORD@localhost:5432/DATABASE`. `--reload` используется только для разработки.

## Локальный запуск frontend

Требуется Node.js 20+:

```powershell
Set-Location frontend
Copy-Item .env.example .env
npm install
npm run dev
```

Адрес API задаётся в `VITE_API_URL`; для локальной разработки значение по умолчанию — `http://localhost:8000/api`. После изменения Vite-переменной перезапустите dev server.

## Миграции

Из папки `backend` с активированным Python-окружением и настроенным `DATABASE_URL`:

```powershell
alembic upgrade head
alembic revision --autogenerate -m "описание изменения"
alembic downgrade -1
```

Перед применением новой autogenerated-миграции всегда просмотрите созданный файл. Текущая первоначальная миграция `823f4c5dc8b6_initial_tables.py` создаёт пользователя и все восемь сущностей planner, внешние ключи, индексы и уникальную пару привычка/день; downgrade удаляет их в обратном порядке.
